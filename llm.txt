# Austrian Landscape Transformation Analysis API — v4.0
# Base URL: https://srtm-lidar-at.exe.xyz:8000
# All geometry input in WGS84 (lon/lat). Processing in EPSG:3035.
# Max query area: 25 km².

## Philosophy

This API answers: "How has man shaped this landscape?"
Watershed-based segmentation classifies 25 individual object types and
11 hierarchical group types, focused on distinguishing man-made from
natural and detecting terrain modification.

## Data Sources (6 layers)

1. BEV ALS DTM + DSM: 1m resolution, EPSG:3035, 3 dates (2022/2023/2024)
2. BEV DOP RGBI Orthophoto: 0.2m resolution, 47 operates covering Austria
3. Copernicus Sentinel-2: 10m NDVI growing-season composite (via openEO)
4. Copernicus ESA WorldCover: 10m land cover classification
5. Copernicus Sentinel-1 SAR: VV+VH backscatter
6. Austrian Cadastre: mm-precision building footprint polygons (ground truth)

## NDVI Fusion

BEV ortho provides 1m spatial detail but has seasonal bias (arbitrary
capture date — could be winter).  Copernicus provides reliable
growing-season median (Apr-Sep) but at coarse 10m resolution that bleeds
across boundaries.  The API fuses both:

  1. Block-average BEV and Copernicus NDVI at ~30m windows
  2. Compute seasonal offset = Copernicus_block − BEV_block
  3. Smooth offset field (σ=15m) to avoid 10m staircase artefacts
  4. fused = BEV + smoothed_offset (clamped to [-1, 1])

Result: 1m spatial precision with growing-season absolute levels.
Fallback: BEV alone → Copernicus alone → no NDVI.

## Key Detection Methods

- **Segmentation**: Sobel fused gradient (DTM+DSM+nDSM+RGBI+NDVI weighted)
  → Felzenszwalb over-segmentation → RAG boundary merge.
  Two-layer: ground (<0.3m) and elevated (≥0.3m) segmented separately.

- **NDVI fusion**: BEV 1m spatial + Copernicus growing-season seasonal
  correction.  Eliminates winter bias while preserving road/grass boundaries.

- **Engineered surfaces**: DTM roughness <0.04m at 3m scale + slope <15°.
  Roads identified even when coarse NDVI shows vegetation bleed.

- **Buildings**: Multi-criteria score (DSM roughness + height uniformity +
  slope + NDVI + brightness + temporal stability + ESA built-up prior).
  Calibrated against BEV cadastre footprints.

- **Disturbance**: Three-tier detection with size gates:
  - Excavation/fill: DTM change >0.20m, ground-level only (≥25m²).
    Elevated objects filtered (DTM noise from tree crown interpolation).
  - Clear_cut: nDSM dropped >2m, terrain intact. Captures individual
    tree death/felling (≥8m²) and larger timber harvest patches.
  - Construction: nDSM grew >2m (non-vegetation), OR tree_loss combined
    with earthworks (DTM change >0.15m = site clearing for development).
  - Vegetation filter: growing trees (high NDVI + rough DSM) excluded
    from construction false positives.

- **Temporal analysis**: 3-date LIDAR (2022/2023/2024) detects terrain
  modification, building construction, tree growth/felling.

## Endpoints

### POST /api/v1/segment  ← PRIMARY
Watershed-based segmentation and classification. 25 types + 11 groups.
Body: GeoJSON geometry
Params:
  dataset           — ALS date (default 20240915)
  min_object_size   — min segment size in pixels/m² (default 30)
  felz_scale        — Felzenszwalb scale, higher = fewer segments (default 150)
  rag_threshold     — RAG merge threshold (default 0.12)
  include_ortho     — "true" for BEV RGBI 1m (NDVI, NIR, brightness)
  include_temporal  — "true" for 3-date LIDAR (2022/2023/2024)
  include_copernicus — "true" for Sentinel-2 NDVI + ESA land cover
  include_cadastre  — "true" for cadastre building footprints
  types             — comma-separated type filter (e.g. "roof,tree,road")
  groups            — comma-separated group filter (e.g. "building,forest")
Returns: FeatureCollection of objects with:
  type, type_code, group_id, group_type, is_manmade, confidence,
  height_max_m, height_mean_m, height_p90_m, area_sqm,
  compactness, elongation, slope_mean, roughness,
  ndvi_mean (BEV 1m), ndvi_fused (seasonal-corrected), nir_mean,
  brightness_mean, height_change, dtm_change, temporal_stability

### POST /api/v1/objects  ⚠️ DEPRECATED — use /api/v1/segment
Legacy 10-type pixel-level landscape classifier.
Still functional but superseded by watershed segmentation.
Params: dataset, min_height, min_area, include_ortho, include_temporal,
  include_copernicus, include_cadastre, object_types
Returns: summary + FeatureCollection with 10 landscape types:
  1=engineered_surface, 2=engineered_slope, 3=excavation, 4=fill,
  5=building, 6=infrastructure, 7=tree_canopy, 8=vegetation,
  9=bare_natural, 10=recent_disturbance

### POST /api/v1/elevation
Enrich features with DSM/DTM elevation values.

### POST /api/v1/terrain
Terrain characterisation: slope, aspect, ruggedness, curvature.

### POST /api/v1/objects/raster
Download classified raster as GeoTIFF.
Band 1: landscape type code (uint8). Band 2: height (float32).

### POST /api/v1/changes
Temporal change detection between two ALS dates.
20 change event types including earthworks, tree felling, construction.

### POST /api/v1/changes/trees
Per-tree growth/felling analysis between dates.

### POST /api/v1/changes/summary
Multi-epoch change summary (2022→2023→2024).

### GET /api/v1/info
Dataset inventory, landscape types, data sources.

### GET /api/v1/docs/llm.txt
This document.

## Geometry Input

All POST endpoints accept:
- GeoJSON Feature or FeatureCollection in body
- {"geometry": <GeoJSON geometry>, ...params} in body
- KML string in body
- Coordinate string: "lon,lat" or "lon,lat;lon,lat;..."
- File upload (multipart)

Point inputs are automatically buffered (100m for objects/segment, 200m for changes).

## Examples

# Watershed segmentation with all data sources
curl -X POST 'https://srtm-lidar-at.exe.xyz:8000/api/v1/segment?include_ortho=true&include_temporal=true&include_copernicus=true' \
  -H 'Content-Type: application/json' \
  -d '{"geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.403,47.07],[15.403,47.073],[15.4,47.073],[15.4,47.07]]]}}'

# Filter to buildings only
curl -X POST 'https://srtm-lidar-at.exe.xyz:8000/api/v1/segment?include_ortho=true&types=roof,wall,greenhouse' \
  -H 'Content-Type: application/json' \
  -d '{"geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.403,47.07],[15.403,47.073],[15.4,47.073],[15.4,47.07]]]}}'

# Change detection
curl -X POST https://srtm-lidar-at.exe.xyz:8000/api/v1/changes \
  -H 'Content-Type: application/json' \
  -d '{"date_a": "20220915", "date_b": "20240915", "geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.41,47.07],[15.41,47.08],[15.4,47.08],[15.4,47.07]]]}}'
