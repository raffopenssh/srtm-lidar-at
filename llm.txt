# Austrian Landscape Transformation Analysis API — v5.0
# Base URL: https://srtm-lidar-at.exe.xyz:8000
# All geometry input in WGS84 (lon/lat). Processing in EPSG:3035.
# Max query area: 25 km². Territory: Austria only.

## Philosophy

This API answers: "How has man shaped this landscape?"
Watershed-based segmentation classifies 25 individual object types and
11 hierarchical group types, focused on distinguishing man-made from
natural and detecting terrain modification.

## Data Sources (6 layers)

1. BEV ALS DTM + DSM: 1m resolution, EPSG:3035, 3 dates (2022/2023/2024)
2. BEV DOP RGBI Orthophoto: 0.2m resolution, 47 operates + DOP RGB fallback
3. Copernicus Sentinel-2: 10m NDVI growing-season composite (via openEO)
4. Copernicus ESA WorldCover: 10m land cover classification
5. Copernicus Sentinel-1 SAR: VV+VH backscatter
6. Austrian Cadastre: mm-precision building footprint polygons (ground truth)

## Step-Change Features (v3.1+)

1. GLCM Texture from 20cm orthophoto (0.5m GLCM → contrast/entropy/homogeneity)
2. NDVI Harmonic Phenology (monthly → mean + amplitude + phase)
3. Sentinel-1 SAR Backscatter (VV+VH — orthogonal to optical)
4. Random Forest Classifier (44-feature vector, cadastre-trained, OOB validation)

## NDVI Fusion

BEV ortho (1m spatial) fused with Copernicus growing-season median (10m):
  fused = BEV + smoothed(Copernicus_block − BEV_block)
Result: 1m spatial precision with growing-season absolute levels.

## Endpoints

### POST /api/v1/segment  ← PRIMARY
Watershed segmentation and classification. 25 types + 11 groups.
Supports async mode for long-running analysis.

Body: GeoJSON, KML, coordinates, or file upload.
Params:
  dataset            ALS date (default 20240915)
  min_object_size    min segment m² (default 30)
  felz_scale         Felzenszwalb scale (default 150)
  rag_threshold      RAG merge threshold (default 0.12)
  include_ortho      "true" for BEV RGBI (NDVI, NIR, brightness)
  include_temporal   "true" for 3-date LIDAR (2022/2023/2024)
  include_copernicus "true" for Sentinel-2 NDVI + ESA land cover + SAR
  include_cadastre   "true" for cadastre building footprints
  include_hansen     "true" for Hansen Global Forest Change calibration
  types              comma-separated type filter (e.g. "roof,tree,road")
  groups             comma-separated group filter (e.g. "building,forest")
  async              "true" → returns 202 with {task_id}, poll progress
  task_id            client-provided UUID for progress tracking

Async flow:
  1. POST /api/v1/segment?async=true → 202 {task_id, status: "running"}
  2. GET  /api/v1/segment/progress?task_id=... → {active, step, detail, elapsed, done, error}
  3. GET  /api/v1/segment/result?task_id=...   → full GeoJSON result

Returns: FeatureCollection with per-object properties:
  type, type_code, group_id, group_type, is_manmade, confidence,
  height_max_m, height_mean_m, height_p90_m, area_sqm,
  compactness, elongation, solidity, extent, dsm_edge_strength,
  slope_mean, roughness, ndvi_mean, ndvi_fused, nir_mean,
  brightness_mean, height_change, dtm_change, temporal_stability,
  glcm_entropy, glcm_homogeneity, texture_complexity,
  sar_vv, sar_vh, harm_amplitude, harm_phase, phenology_class

### POST /api/v1/elevation
Enrich features with DSM/DTM elevation values.

### POST /api/v1/terrain
Terrain characterisation: slope, aspect, ruggedness, curvature.

### POST /api/v1/changes
Temporal change detection between two ALS dates.
20 change event types including earthworks, tree felling, construction.

### POST /api/v1/changes/trees
Per-tree growth/felling analysis between dates.

### POST /api/v1/changes/summary
Multi-epoch change summary (2022→2023→2024).

### POST /api/v1/export/geopackage
Export all layers as a single GeoPackage file.
Supports async mode (async=true → poll + download).
Params:
  include_dtm        DTM/DSM/nDSM bands (default true)
  include_dsm        same as above
  include_segments   segment_type + segment_height bands
  ortho_years        comma-separated (e.g. 2024,2023)
  raster_layers      comma-separated overlay IDs to render as RGBA
  types              segment type filter
  color_mode         type|height
  async              "true" → 202 with {task_id}
Async flow:
  1. POST /api/v1/export/geopackage?async=true → 202 {task_id}
  2. GET  /api/v1/segment/progress?task_id=... → poll
  3. GET  /api/v1/export/geopackage/download/{task_id} → binary .gpkg

### POST /api/v1/segment/overlay
Rendered RGBA PNG overlay of segmentation results.
Params: types, color_mode (type|height)

### GET /api/v1/layers?bbox=lon_min,lat_min,lon_max,lat_max
Return which data layers are available for a bounding box.
Response:
  {
    "ortho": {"2024": true, "2023": false, "2020": true},
    "cir":   {"2024": true, "2023": false, "2020": false},
    "dtm":   {"2024": true, "2023": true, "2022": true},
    "dsm":   {"2024": true, "2023": true, "2022": true},
    "hansen": true
  }
Ortho falls back to DOP RGB tiles (~2020/2022 vintage).
CIR requires RGBI operates with NIR band (no fallback).

### GET /api/v1/info
Dataset inventory, landscape types, data sources.

### GET /api/v1/training/status
RF classifier training job status, current KG, model info.

### POST /api/v1/classifier/train
Train/retrain the Random Forest classifier on cadastre ground truth.
Params: bbox (lon_min,lat_min,lon_max,lat_max), n_estimators, max_depth

### Overlay endpoints (POST, return PNG with X-Bounds header)
  /api/v1/dtm/overlay      DTM hillshade
  /api/v1/dsm/overlay      nDSM height overlay (viridis colormap)
  /api/v1/ortho/overlay    RGB orthophoto
  /api/v1/cir/overlay      Color Infrared false-color (NIR→R, R→G, G→B)
  /api/v1/hansen/overlay    Hansen forest change overlay
  /api/v1/lidar/overlay     Combined DTM+DSM overlay

### GET /api/v1/lidar/geotiff, /api/v1/ortho/geotiff
Download raw raster data as GeoTIFF.

## Geometry Input

All POST endpoints accept:
- GeoJSON Feature or FeatureCollection in body
- {"geometry": <GeoJSON>, ...params} in body
- KML string in body
- Coordinate string: "lon,lat" or "lon,lat;lon,lat;..."
- File upload (multipart: KML, GeoJSON, Shapefile, GPX)

Multi-feature inputs (FeatureCollection, multi-placemark KML) are
automatically unioned into a single convex hull boundary.
Geometries outside Austria (lon 9.5-17.2, lat 46.3-49.0) are rejected.
Areas exceeding 25 km² are rejected.
Point inputs are buffered to 100m radius.

## Examples

# Async watershed segmentation with all data sources
curl -X POST 'https://srtm-lidar-at.exe.xyz:8000/api/v1/segment?async=true&include_ortho=true&include_temporal=true&include_copernicus=true&include_cadastre=true' \
  -H 'Content-Type: application/json' \
  -d '{"geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.403,47.07],[15.403,47.073],[15.4,47.073],[15.4,47.07]]]}}'
# → {"task_id": "...", "status": "running"}

# Poll progress
curl 'https://srtm-lidar-at.exe.xyz:8000/api/v1/segment/progress?task_id=...'

# Get result
curl 'https://srtm-lidar-at.exe.xyz:8000/api/v1/segment/result?task_id=...'

# Check layer availability
curl 'https://srtm-lidar-at.exe.xyz:8000/api/v1/layers?bbox=15.1,47.1,15.2,47.2'

# Change detection
curl -X POST https://srtm-lidar-at.exe.xyz:8000/api/v1/changes \
  -H 'Content-Type: application/json' \
  -d '{"date_a": "20220915", "date_b": "20240915", "geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.41,47.07],[15.41,47.08],[15.4,47.08],[15.4,47.07]]]}}'
