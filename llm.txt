# Austrian Landscape Transformation Analysis API — v3.0
# Base URL: https://srtm-lidar-at.exe.xyz:8000
# All geometry input in WGS84 (lon/lat). Processing in EPSG:3035.
# Max query area: 25 km².

## Philosophy

This API answers: "How has man shaped this landscape?"
Instead of 27 fragile object types, we classify 10 landscape types focused
on distinguishing man-made from natural, and detecting terrain modification.

## Data Sources (6 layers)

1. BEV ALS DTM + DSM: 1m resolution, EPSG:3035, 3 dates (2022/2023/2024)
2. BEV DOP RGBI Orthophoto: 0.2m resolution, 47 operates covering Austria
3. Copernicus Sentinel-2: 10m NDVI growing-season composite (via openEO)
4. Copernicus ESA WorldCover: 10m land cover classification
5. Copernicus Sentinel-1 SAR: VV+VH backscatter
6. Austrian Cadastre: mm-precision building footprint polygons (ground truth)

## 10 Landscape Types

| Code | Type | Description |
|------|------|-------------|
| 1 | engineered_surface | Roads, parking, paved — flat, smooth at 1m scale |
| 2 | engineered_slope | Embankments, cuttings, retaining walls — linear terrain features |
| 3 | excavation | Quarries, pits, construction sites — terrain removed |
| 4 | fill | Landfill, raised platforms, levees — terrain added |
| 5 | building | Structures: height + stability + spectral evidence |
| 6 | infrastructure | Bridges, masts, fences, walls, other man-made elevated |
| 7 | tree_canopy | All trees (no conifer/broadleaf split needed) |
| 8 | vegetation | Low veg, shrubs, meadows, crops |
| 9 | bare_natural | Rock, cliff, bare soil, natural water |
| 10 | recent_disturbance | Terrain modified between LIDAR dates (machinery traces) |

## Key Detection Methods

- **Linear features**: Hessian eigenvalue analysis on DTM detects ridges (embankments)
  and valleys (ditches) — identifies engineered vs natural terrain form
- **Engineered surfaces**: Multi-scale roughness ratio (3m/15m window) detects
  unnaturally smooth terrain (roads, parking)
- **Machinery traces**: DTM time series differencing with spatial coherence filtering
  detects where excavators/bulldozers reshaped terrain
- **Buildings**: Multi-criteria score (DSM roughness + height uniformity + terrain
  slope + NDVI + temporal stability). Calibrated against BEV cadastre footprints.
- **Building F1=0.70** with ortho (P=0.56, R=0.92). Temporal + Copernicus improve further.

## Endpoints

### POST /api/v1/objects
Landscape classification. 10 types from LIDAR + optional enrichment.
Body: GeoJSON geometry
Params:
  dataset           — ALS date (default 20240915)
  min_height        — min object height in metres (default 0.2)
  min_area          — min object area in m² (default 2)
  include_ortho     — "true" to use BEV RGBI orthophoto (adds NDVI, improves buildings)
  include_temporal  — "true" to use 3-date LIDAR (2022/2023/2024).
                      Detects machinery traces, building stability, tree growth.
                      Costs ~3x loading time but dramatically improves accuracy.
  include_copernicus — "true" to use Sentinel-2 NDVI + ESA land cover (10m, via openEO).
                       Provides reliable growing-season NDVI (eliminates seasonal bias).
  include_cadastre  — "true" to use cadastre building footprints for calibration.
  object_types      — comma-separated type filter
Returns: summary + FeatureCollection of objects with:
  type, type_code, is_manmade, confidence, linear_feature, machinery_trace,
  height_max_m, area_sqm, temporal_signal, ndvi_mean

Each object includes:
- is_manmade (bool): the key question answered
- confidence (0-1): how certain the classification is
- linear_feature (bool): detected as linear man-made feature
- machinery_trace (bool): terrain shows machinery modification

### POST /api/v1/elevation
Enrich features with DSM/DTM elevation values.

### POST /api/v1/terrain
Terrain characterisation: slope, aspect, ruggedness, curvature.

### POST /api/v1/objects/raster
Download classified raster as GeoTIFF.
Band 1: landscape type code (uint8). Band 2: height (float32).

### POST /api/v1/changes
Temporal change detection between two ALS dates.
20 change event types including earthworks, tree felling, construction.

### POST /api/v1/changes/trees
Per-tree growth/felling analysis between dates.

### POST /api/v1/changes/summary
Multi-epoch change summary (2022→2023→2024).

### GET /api/v1/info
Dataset inventory, landscape types, data sources.

### GET /api/v1/docs/llm.txt
This document.

## Geometry Input

All POST endpoints accept:
- GeoJSON Feature or FeatureCollection in body
- {"geometry": <GeoJSON geometry>, ...params} in body
- KML string in body
- Coordinate string: "lon,lat" or "lon,lat;lon,lat;..."
- File upload (multipart)

Point inputs are automatically buffered (100m for objects, 200m for changes).

## Examples

# Basic classification (LIDAR only)
curl -X POST https://srtm-lidar-at.exe.xyz:8000/api/v1/objects \
  -H 'Content-Type: application/json' \
  -d '{"geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.403,47.07],[15.403,47.073],[15.4,47.073],[15.4,47.07]]]}}'

# Full analysis with all data sources
curl -X POST 'https://srtm-lidar-at.exe.xyz:8000/api/v1/objects?include_ortho=true&include_temporal=true' \
  -H 'Content-Type: application/json' \
  -d '{"geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.403,47.07],[15.403,47.073],[15.4,47.073],[15.4,47.07]]]}}'

# Change detection
curl -X POST https://srtm-lidar-at.exe.xyz:8000/api/v1/changes \
  -H 'Content-Type: application/json' \
  -d '{"date_a": "20220915", "date_b": "20240915", "geometry": {"type": "Polygon", "coordinates": [[[15.4,47.07],[15.41,47.07],[15.41,47.08],[15.4,47.08],[15.4,47.07]]]}}'
